Standards & Conventions

Host Naming Convention

Consistent hostname schema used across all lab infrastructure — VPS hosts, cloud instances, physical devices, VMs and containers.

[hyperscaler-]xxx-yyy<nn>[.role].clb-sol.dev
[hyperscaler-] — optional prefix, only present for cloud IaaS instances xxx — site / location prefix yyy — function / role of host nn — two-digit sequence number [.role] — optional service role subdomain
Examples

Hostnames in the wild

vps-mon01.clb-sol.dev
vps — VPS at external hoster · mon — monitoring · 01 — first instance
oci-fra-app01.clb-sol.dev
oci — hyperscaler (Oracle Cloud Infrastructure) · fra — site (region Frankfurt) · app — generic application / docker host · 01 — first instance
hau-hyp01.pve.clb-sol.dev
hau — Hanau (DE HAU) · hyp — hypervisor · 01 — node 1 of cluster · .pve - Proxmox Virtual Environment
hau-lgw01.wxc.clb-sol.dev
hau — site · lgw — Local Gateway · 01 — first instance · .wxc — Webex Calling service role
hau-ctl01.pzs.clb-sol.dev
hau — site · ctl — controller · 01 — first instance · .pzs — physical access system role
Optional · hyperscaler-

Hyperscaler Prefix

Prepended in front of the normal xxx-yyy<nn> schema, only for cloud IaaS compute instances (Oracle Cloud Infrastructure, AWS, Azure, …) — a materially different kind of resource — part of a larger elastic cloud platform rather than a single rented VM. Omitted entirely for on-prem hosts (hau) and classic flat-rate VPS products (vps). fra-app01 would be a genuine physical/owned presence in Frankfurt; oci-fra-app01 is the same location, just hosted via a hyperscaler instead.

Part 1 · xxx

Site / Location Prefix

UN/LOCODE reference: German sites use the 3-letter code directly (e.g. hau). Sites outside Germany prepend the ISO 3166-1 alpha-2 country code: nl-ams, us-nyc. For a hyperscaler-hosted instance, xxx is still just the UN/LOCODE of the region the instance physically runs in (e.g. fra) — the hyperscaler goes in front as its own optional prefix, see above.

Containers

Naming Containers

A container is named exactly like any other host — there is no separate container syntax, no nesting, no parent-host reference in the name. It simply inherits the prefix of the host it runs on (hyperscaler prefix included, if present) and gets its own function code and sequence number, same as a VM or a physical device would.

xxx-yyy<nn>
Container on a plain host — inherits just the site prefix, gets its own function and sequence.
hyperscaler-xxx-yyy<nn>
Container on a cloud IaaS instance — inherits the full hyperscaler+site prefix the same way.
Sequence · nn

Numbering

Two-digit zero-padded integer starting at 01. Numbers are assigned per function within a site — not globally. A second hypervisor at the same site becomes hau-hyp02, while a hypervisor at a different site starts again at -hyp01.
